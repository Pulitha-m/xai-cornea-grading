# ML Service

FastAPI inference service for Corneal-AI. The backend sends it the actual image bytes; the service validates the image, checks that it is a specular microscopy image of the corneal endothelium, and only then runs the analysis modules.

## Request flow

```
Browser ──multipart──► Backend POST /api/analysis/images   (checks size, signature, dimensions;
                                                             stores in a private Supabase bucket)
Browser ──JSON {caseId, imageId, ecd}──► Backend POST /api/analysis
          Backend: owner check → reads the stored bytes → SHA-256 integrity check
          Backend ──multipart {caseId, ecd, image}──► ml-service POST /analyze
          ml-service: decode → domain validation → modules → response
```

Images are never referenced by URL. Storage paths are generated by the backend, and only the user who uploaded an image may analyse it.

## `POST /analyze`

Multipart form fields:

| Field | Required | Meaning |
|---|---|---|
| `image` | yes | The image file (JPEG or PNG) |
| `caseId` | yes | Case identifier |
| `ecd` | no | Endothelial cell density (cells/mm²) from the specular microscopy report; `0 < ecd ≤ 6000` |

Processing order: input checks → image decoding → domain validation → modules. A failure at any step returns a rejection and no module runs:

```json
{"status": "rejected", "error": {"code": "INVALID_IMAGE_DOMAIN", "field": "image", "message": "Upload a specular microscopy image showing corneal endothelial cells."}}
```

| Code | HTTP | Cause |
|---|---|---|
| `IMAGE_DECODE_FAILED` | 422 | Empty, truncated or unreadable file, or missing image |
| `UNSUPPORTED_IMAGE_FORMAT` | 422 | Not JPEG or PNG (judged by content, not extension) |
| `IMAGE_TOO_LARGE` | 422 | Over `IMAGE_MAX_BYTES` |
| `IMAGE_DIMENSIONS_INVALID` | 422 | Sides outside `IMAGE_MIN_SIDE`–`IMAGE_MAX_SIDE`, or more than `IMAGE_MAX_PIXELS` (decompression bombs are rejected from the header) |
| `INVALID_IMAGE_DOMAIN` | 422 | Not a specular microscopy image of the corneal endothelium |
| `CORNEAL_IMAGE_UNCERTAIN` | 422 | Validator score in the uncertain band |
| `INVALID_FEATURE_TYPE` / `FEATURE_OUT_OF_RANGE` | 422 | Malformed or out-of-range `ecd` |
| `MODEL_NOT_READY` | 503 | Domain validator artifacts missing or mismatched (fails closed) |

A successful response has `status` `completed` (every module completed) or `partial`, plus `imageValidation` and one result per module. Modules run independently: `not_implemented` and `failed` modules carry no values, and nothing is substituted.

## Domain validator

`pipelines/image/domain.py`, artifacts in `models/domain_validator/`. It answers one question: *is this a specular microscopy image of the corneal endothelium, like those the system was built for?* It does **not** assess image quality, cell visibility or disease; `imageValidation.qualityAssessed` is always `false`.

**Model:** ImageNet ResNet-18 features (frozen, ONNX) + standardisation + logistic regression. Every image is converted to greyscale first, so colour cannot be used as a shortcut.

**Training and evaluation** (`ml/grading/scripts/train_domain_validator.py`):
- **Positives:** 1,024 de-duplicated specular microscopy images, split 60/20/20 by inferred donor.
- **Negatives:** COCO val2017 photographs, synthetic documents and screenshots, and synthetic content-free images (uniform, gradients, noise, stripes, checkerboards), split 60/20/20.
- **Thresholds:** chosen on the validation split only. Reject below 0.50; accept at or above 0.61, just above the highest validation-negative score; scores in between are `CORNEAL_IMAGE_UNCERTAIN`.

**Held-out test results (v2):**

| Test images | n | Accepted as corneal |
|---|---:|---:|
| All negatives | 1,295 | 0 |
| … COCO: people / animals / vehicles / food / indoor | 559 / 198 / 239 / 144 / 115 | 0 each |
| … COCO: buildings / landscapes (caption-defined) | 114 / 198 | 0 each |
| … synthetic documents / screenshots / content-free | 76 / 84 / 140 | 0 each |
| Specular microscopy images | 197 | 197 |
| … grade B (abnormal) tissues | 30 | 30 |
| … blurred (radius 2 and 5) or downscaled copies | 197 each | 197 each |

With zero errors in these sample sizes, the 95% upper bounds are about 0.23% false acceptance and 1.5% false rejection, for **these kinds of images**.

**Version history:** v1 had no content-free negatives. A regression test written before training showed it accepted flat grey, black and noise images (scores 0.94–0.995). v2 added content-free negatives; its v1 results are kept in `evaluation_v1.json`.

**Limitations (not evaluated):**
- All positives come from one eye bank's specular microscope. Images from other microscope models, magnifications or exports may be rejected.
- No near-domain negatives were tested: other microscopy, histology, slit-lamp or other eye photographs, or images of other cell types. Some of these may be accepted.
- It does not detect poor focus or insufficient cell detail; heavily blurred specular images were accepted.
- This is an engineering check of input type, **not a clinically validated classifier**.

Full results: `models/domain_validator/evaluation.json`.

## Grading

ECD threshold tree selected in `ml/grading/notebooks/images/13_nested_tuning_model_selection.ipynb`: neither a tuned 24-feature tabular model nor a tuned tabular + image model convincingly outperformed it (`ml/grading/RESULTS.md`).

| ECD (cells/mm²) | Grade |
|---|---|
| ≤ 2232 | B |
| > 2232 and ≤ 2497 | A |
| > 2497 | A+ |

- **Decision support only.** The grade uses ECD alone; slit-lamp findings and other morphology are not considered and may justify a lower grade. A specialist confirms every grade.
- **No ECD** → `review_required` with no grade.
- **Not a confidence score:** `bandDistribution` reports the recorded grades of training tissues in the same ECD band. No calibration was assessed.
- **Spec:** `models/grading_ecd_tree.json`. Regenerate it with `ml/grading/scripts/train_grading_model.py` (needs the git-ignored grading dataset).

### 24-feature schema

`models/grading_feature_schema.json` is exported from the training code by `ml/grading/scripts/export_feature_schema.py`. It records order, types, units, categories, missing-value handling and training ranges for the 24 tabular features. `pipelines/grading/feature_schema.py` validates payloads against it:
- missing keys and unknown keys are errors;
- `null` means "not recorded" and is handled as in training;
- malformed or impossible values are errors;
- values outside the training range, and an ECD inconsistent with count/area, are warnings.

The deployed grade uses only ECD. The schema is the contract for any future tabular inference, and `tests/test_feature_schema.py` checks it against the training code's feature lists.

## Other modules

Cellular analysis, disease screening and recommendation return `not_implemented` with no values. A disease model exists in `ml/disease - new/` but has not been integrated or evaluated here.

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `IMAGE_MAX_BYTES` | 15728640 | Maximum upload size (keep equal to the backend's) |
| `IMAGE_MIN_SIDE` / `IMAGE_MAX_SIDE` | 224 / 8000 | Allowed side lengths in pixels |
| `IMAGE_MAX_PIXELS` | 40000000 | Maximum total pixels |
| `DOMAIN_VALIDATOR_DIR` | `models/domain_validator` | Validator artifacts |
| `DOMAIN_VALIDATOR_DEV_BYPASS` | unset | **Development only.** `true` skips domain validation; responses are marked `UNVALIDATED_DEV_MODE` and never valid |

## Docker and the ONNX backbone

The backbone (`resnet18_backbone.onnx`, about 45 MB) is not in git. The Dockerfile regenerates it in a build stage:
- `scripts/export_domain_backbone.py` runs with pinned `torch==2.14.1` and `torchvision==0.29.1` (CPU).
- torchvision downloads the ResNet-18 IMAGENET1K_V1 weights from their versioned, hash-named URL.
- The script **verifies the exported file's SHA-256 against `classifier.json`**, so the build fails if the backbone ever differs from the one the classifier was trained with. The export is byte-for-byte reproducible: CUDA build on Windows and CPU build on Linux gave the same hash.
- A local `.onnx` is excluded from the build context.

Licences: torchvision is BSD-3-Clause; the pretrained weights were trained on ImageNet ([terms](https://pytorch.org/vision/stable/models.html)). COCO images were used for training and evaluation only and are not distributed.

For local development without Docker, generate the backbone once:

```
cd ml
.venv/Scripts/python.exe ../ml-service/scripts/export_domain_backbone.py ../ml-service/models/domain_validator/resnet18_backbone.onnx --verify ../ml-service/models/domain_validator/classifier.json
```

## Tests

```
uv sync
uv run pytest
```

- **Without the backbone file:** tests that need the real validator are skipped; all other tests stub it.
- **Backend `MlServiceContractTest`:** checks captured responses against the backend DTOs. When the schema changes, regenerate `backend/src/test/resources/contracts/ml_service_analyze_responses.json` from this service.
