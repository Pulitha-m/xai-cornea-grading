# ML Service

FastAPI inference service for Corneal-AI. The backend sends it the actual image bytes; the service validates the image, checks that it is a specular microscopy image of the corneal endothelium, and only then runs the analysis modules.

## Request flow

```
Browser ──multipart──► Backend POST /api/analysis/images   (checks size, signature, dimensions;
                                                             stores in a private Supabase bucket)
Browser ──JSON {caseId, imageId, clinicalFeatures}──► Backend POST /api/analysis
          Backend: owner check → reads the stored bytes → SHA-256 integrity check
          Backend ──multipart {caseId, clinicalFeatures, image}──► ml-service POST /analyze
          ml-service: decode → domain validation → modules → response
```

Images are never referenced by URL. Storage paths are generated by the backend, and only the user who uploaded an image may analyse it.

## `POST /analyze`

Multipart form fields:

| Field | Required | Meaning |
|---|---|---|
| `image` | yes | The image file (JPEG or PNG) |
| `caseId` | yes | Case identifier |
| `clinicalFeatures` | yes | JSON object with all 24 grading features (see [24-feature schema](#24-feature-schema)); `null` = not recorded |

Processing order: input checks → image decoding → domain validation → modules. A failure at any step returns a rejection and no module runs:

```json
{"status": "rejected", "error": {"code": "INVALID_IMAGE_DOMAIN", "field": "image", "message": "Upload a specular microscopy image showing corneal endothelial cells."}}
```

| Code | HTTP | Cause |
|---|---|---|
| `IMAGE_DECODE_FAILED` | 422 | Empty, truncated or unreadable file, or missing image |
| `UNSUPPORTED_IMAGE_FORMAT` | 422 | Not JPEG or PNG (judged by content, not extension) |
| `IMAGE_TOO_LARGE` | 422 | Over `IMAGE_MAX_BYTES` |
| `IMAGE_DIMENSIONS_INVALID` | 422 | Sides outside `IMAGE_MIN_SIDE`–`IMAGE_MAX_SIDE`, or more than `IMAGE_MAX_PIXELS` (decompression bombs are rejected from the header) |
| `INVALID_IMAGE_DOMAIN` | 422 | Not a specular microscopy image of the corneal endothelium |
| `CORNEAL_IMAGE_UNCERTAIN` | 422 | Validator score in the uncertain band |
| `MISSING_CLINICAL_FEATURES` / `FEATURE_SCHEMA_MISMATCH` | 422 | `clinicalFeatures` missing, not a JSON object, or with missing/unknown keys |
| `INVALID_FEATURE_TYPE` / `FEATURE_OUT_OF_RANGE` | 422 | Malformed or impossible feature value; every such error is listed in `errors` with its `field` |
| `MODEL_NOT_READY` | 503 | Domain validator artifacts missing or mismatched (fails closed) |

A successful response has `status` `completed` (every module completed) or `partial`, plus `imageValidation` and one result per module. Modules run independently: `not_implemented` and `failed` modules carry no values, and nothing is substituted.

## Domain validator

`pipelines/image/domain.py`, artifacts in `models/domain_validator/`. It answers one question: *is this a specular microscopy image of the corneal endothelium, like those the system was built for?* It does **not** assess image quality, cell visibility or disease; `imageValidation.qualityAssessed` is always `false`.

**Model:** ImageNet ResNet-18 features (frozen, ONNX) + standardisation + logistic regression. Every image is converted to greyscale first, so colour cannot be used as a shortcut.

**Training and evaluation** (`ml/grading/scripts/train_domain_validator.py`):
- **Positives:** 1,024 de-duplicated specular microscopy images, split 60/20/20 by inferred donor.
- **Negatives:** COCO val2017 photographs, synthetic documents and screenshots, and synthetic content-free images (uniform, gradients, noise, stripes, checkerboards), split 60/20/20.
- **Thresholds:** chosen on the validation split only. Reject below 0.50; accept at or above 0.61, just above the highest validation-negative score; scores in between are `CORNEAL_IMAGE_UNCERTAIN`.

**Held-out test results (v2):**

| Test images | n | Accepted as corneal |
|---|---:|---:|
| All negatives | 1,295 | 0 |
| … COCO: people / animals / vehicles / food / indoor | 559 / 198 / 239 / 144 / 115 | 0 each |
| … COCO: buildings / landscapes (caption-defined) | 114 / 198 | 0 each |
| … synthetic documents / screenshots / content-free | 76 / 84 / 140 | 0 each |
| Specular microscopy images | 197 | 197 |
| … grade B (abnormal) tissues | 30 | 30 |
| … blurred (radius 2 and 5) or downscaled copies | 197 each | 197 each |

With zero errors in these sample sizes, the 95% upper bounds are about 0.23% false acceptance and 1.5% false rejection, for **these kinds of images**.

**Version history:** v1 had no content-free negatives. A regression test written before training showed it accepted flat grey, black and noise images (scores 0.94–0.995). v2 added content-free negatives; its v1 results are kept in `evaluation_v1.json`.

**Limitations (not evaluated):**
- All positives come from one eye bank's specular microscope. Images from other microscope models, magnifications or exports may be rejected.
- No near-domain negatives were tested: other microscopy, histology, slit-lamp or other eye photographs, or images of other cell types. Some of these may be accepted.
- It does not detect poor focus or insufficient cell detail; heavily blurred specular images were accepted.
- This is an engineering check of input type, **not a clinically validated classifier**.

Full results: `models/domain_validator/evaluation.json`.

## Grading

The grade comes from the tuned hybrid Random Forest on the 24 features and the image (`pipelines/grading/hybrid.py`, `method: hybrid_random_forest_24_resnet50`). This is a project decision recorded as Amendment 2 in `ml/grading/ANALYSIS_PLAN.md`: notebook 13's rule had selected the ECD tree, and the hybrid was **not better** than it (macro F1 −0.003 [−0.034, +0.029]) or than the tuned tabular model (−0.012), Holm p = 1.00.

- **Model:** `models/grading_hybrid_rf.joblib` (PCA 32 components, `min_samples_leaf=1, max_depth=15, max_features=0.3`, no class weighting), with notebook 13's preprocessing. Its SHA-256 and the backbone's reference output are recorded in `grading_hybrid_rf.json`; the service refuses a model file that does not match or a backbone that has not been verified against it, and grading then reports `failed` with no grade. Regenerate with `ml/grading/scripts/train_hybrid_grading_model.py` (needs the git-ignored grading dataset and embeddings).
- **Image features:** ResNet-50 (ImageNet IMAGENET1K_V2) on the full-resolution greyscale image, as in training. Every training image was 1296 × 972; other sizes are resized to that and reported as an `IMAGE_NOT_TRAINING_SIZE` warning. 551 of 551 training tissues get the same prediction with the served ONNX embeddings as with the research embeddings (largest tree-vote difference 0.060; embeddings differ by at most 0.4% relative).
- **Estimated performance** (notebook 13, donor-grouped nested CV): macro F1 0.793 ± 0.047, grade B recall 0.79 ± 0.13.
- **`modelProbabilities`:** the share of trees voting for each grade. **Not calibrated; not a confidence.**
- **Missing inputs:** `null` features are handled as in training and listed in `featuresNotRecorded`.
- **`warnings`:** schema warnings (outside the training range, ECD inconsistent with count/area) and the image-size warning. Any warning sets `reviewRequired`.
- **Decision support only.** A specialist confirms every grade.

**ECD reference (`ecdReference`).** The ECD threshold tree from notebook 13 is computed alongside as the single-feature baseline (`models/grading_ecd_tree.json`, from `ml/grading/scripts/train_grading_model.py`):

| ECD (cells/mm²) | Grade |
|---|---|
| ≤ 2232 | B |
| > 2232 and ≤ 2497 | A |
| > 2497 | A+ |

It reports the band and the recorded grades of training tissues in that band. When ECD is not recorded, `ecdReference.status` is `review_required` with no grade and the overall `reviewRequired` is true.

**Grading on its own page.** `POST /grading/analyze` (`app/routers/grading.py`) runs only grading and is shown on the "Cornea grading" page (backend `POST /api/analysis/grading`, runs recorded in `grading_analysis_runs`). Same form fields and request handling as `/analyze` (features validated first, then decoding and the domain validator). The grading fields are returned at the top level, plus `featuresUsed` (the validated 24 features). A grading failure is a rejection rather than a `failed` module: `503 MODEL_NOT_READY` when the model or backbone is unavailable, `500 MODEL_INFERENCE_FAILED` otherwise. `/analyze` still grades as before.

**Explanation (`explanation`, `/grading/analyze` only).** `pipelines/grading/explain.py`; `null` if it fails (the grade is still returned).
- **SHAP:** path-dependent TreeSHAP (`shap.TreeExplainer`) on the forest, explaining the predicted grade's share of tree votes. `baseline` (training average) + the 24 inputs' contributions + `imageContribution` = `prediction`, exactly. One-hot columns are summed into their input; the 32 PCA image components into `imageContribution`.
- **Image map (`imageMap`):** *not* Grad-CAM: the forest has no gradients. The path from ResNet-50's layer4 maps to the forest is linear (spatial mean → standardisation → PCA, not whitened), so the image's SHAP value is split exactly over locations: component *j*'s value in proportion to each location's PCA score. Components with |score| < 0.1 training SD are left out (`localisedShare` = share mapped). Two overlays: regions that raised (`supportingPng`) and lowered (`opposingPng`) the share, each scaled to its own maximum, with their sums (`supportingTotal`, `opposingTotal`). The feature maps are the backbone's second ONNX output (`feature_maps`, added in `scripts/export_grading_backbone.py`; output 0 is still the verified pooled features). With a backbone exported without it, `imageMap` is `null`.
- **Limits:** explains the model, not the cornea; not causal; faithfulness not evaluated. On a training image the maps peaked at the out-of-focus bottom border — check across images before reading the maps clinically.
- Adds the `shap` dependency (with numba); imported and built at startup (~4 s), ~0.01 s per request.

### 24-feature schema

`models/grading_feature_schema.json` is exported from the training code by `ml/grading/scripts/export_feature_schema.py`. It records order, types, units, categories, missing-value handling and training ranges for the 24 tabular features. `pipelines/grading/feature_schema.py` validates payloads against it:
- missing keys and unknown keys are errors;
- `null` means "not recorded" and is handled as in training;
- malformed or impossible values are errors;
- values outside the training range, and an ECD inconsistent with count/area, are warnings.

Every grading request passes this validator. `tests/test_feature_schema.py` checks the schema against the training code's feature lists, and the frontend's feature list is checked against it in `frontend/src/lib/grading-features.test.ts`.

## Disease detection and severity (v2)

`POST /disease/analyze` (`app/routers/disease.py`, `pipelines/disease/`), shown on its own "Disease screening" page (backend `POST /api/analysis/disease`). It is **not** run by `/analyze`, whose `disease` module stays `not_implemented`. Port of `ml/disease-new/notebooks/10_Inference_Final_Models_v2.ipynb`. **Research tool, not a medical diagnosis.**

Multipart form fields: `image`, `caseId`, `measurements` (JSON object with exactly `ECD_CD_cells_per_mm2`, `SD`, `CV`, `HEX_percent`, `Donor_Age`; `null` = not recorded, never 0) and optional `force`.

Processing order: measurement types → `decode_image` → domain validator (same rejections as `/analyze`) → the notebook's input checks → models.
- **Input checks:** greyscale (colour score ≤ 3), shorter side ≥ 300 px, aspect 1.1–1.6 (warning), quality (contrast, saturation → unusable; focus below the 5th percentile of training images, or dark → low, warning), unusual image (k = 5 cosine kNN distance to the 1,222 training images: warning above the 95th, error above the 99th percentile of test distances), values within possible ranges, outside the training range (warning), SD ≈ CV/100 × 10⁶ / ECD within 5 %, at most 2 values missing (missing ones get the training median, with a warning). Errors give `422 INPUT_CHECK_FAILED` with every error and warning in `inputCheck`, unless `force` is true; a forced result has `inputCheck.forced: true` and `reliable: false`.
- **Models:** DenseNet121 image + numbers fusion (5 diseases: FECD, Guttata, Folds, PolyPleo, LowCD) and the multi-task severity model (FECD group, Folds, Guttata: Mild or Mod/Sev). Image: greyscale → 384 × 288 → ImageNet normalisation; mean of the image and its horizontal flip. A disease is found at or above its cross-validated threshold; the overall severity is the worst detected group. Grad-CAM of the disease model's `features` layer per detected disease, as base64 PNG.
- **SHAP for the numbers** (`pipelines/disease/explain.py`): exact Shapley values (all 32 coalitions) of the five values (ECD together with its derived ECD_Deficit, SD, CV, HEX %, age) for every disease probability and each model-graded severity group, with the image fixed (the backbone runs once; only the layers after it are re-run from `heads.npz`). Missing inputs take the training median, which is also the baseline, so a value not recorded contributes 0 and `baseline + Σ contributions = prediction` (probability units). Grad-CAM explains the image, SHAP the values.
- **Reading a CellChek report** (`POST /disease/read-report`, `pipelines/disease/report.py`): optional pre-fill of the five values from a picture of the CellChek report (JPEG/PNG, RapidOCR on onnxruntime, about 4 s on CPU) or its `.txt` export. Each value is the number right of its label; readings are cross-checked (CD = Total Num / Total Area within 3 %, SD = CV × mean cell area within 5 %), impossible values are dropped and hard-to-read ones flagged. The report is not stored and is never the model's image. `opencv-python` (required by rapidocr) is overridden in `pyproject.toml` so only the headless OpenCV is installed. Tests use a synthetic report; no real report is committed.
- **Artifacts** (`models/disease_v2/`, committed): `corneal_config.json` (number scaling, thresholds, check limits, the models' SHA-256; exported by `ml/disease-new/scripts/export_corneal_config.py`), the two ONNX models and `heads.npz` (from the trained `.pt` files by `export_onnx_models.py`, which checks the ONNX outputs and the numpy heads against torch and the in-graph Grad-CAM against autograd) and `ood_reference_v2.npz`. Loaded once at startup; files that do not match the config's SHA-256 give `503 MODEL_NOT_READY`.
- **Parity:** `tests/test_disease_parity.py` runs the service pipeline on `ml/disease-new/data/test_images/` (git-ignored) and compares with the notebook's saved test predictions; the maximum difference must be < 0.01 (currently 0.0028). Skipped where the data is absent. Print the table with `uv run python -m tests.test_disease_parity`.

## Cellular analysis (Component 3)

`POST /cellular/analyze` (`app/routers/cellular.py`, `pipelines/cellular/`), on its own page (backend `POST /api/analysis/cellular`). It is **not** run by `/analyze`, whose `cellular` module stays `not_implemented`. It serves the validated pipeline of `ml/cellular/pipeline.py`. **Research tool for a specialist, not a clinical measurement.**

Multipart form fields: `image`, `caseId`. Processing order: `decode_image` (same limits) → domain validator (same rejections as `/analyze`) → the pipeline. The pipeline gets the uploaded bytes decoded with OpenCV (greyscale), as in the research, so the served numbers match it.

- **Steps:**
  1. **ROI:** EfficientNet-B0 on 162 px tiles with a half-tile stride. P(analysable) is averaged per pixel; the ROI is P ≥ 0.5 inside the lit area, with small parts and holes removed.
  2. **Cells:** StarDist on the flat-preprocessed image, normalised over the lit area.
  3. **Complete cells:** cells touching the image border or the unanalysable area are excluded; side counts are taken only for fully surrounded cells.
  4. **Biomarkers:** ECD, mean and SD of the cell area, CV, HEX, compactness and the distributions, at the calibrated scale of 0.796 µm/px.
- **Explanations (they never change a number):**
  - quality flags (`error` = not reliable);
  - 95 % CIs of ECD, CV and HEX by bootstrap over 64 px blocks of cells (sampling only, not segmentation error);
  - the share of the area variance from the 5 % most extreme cells;
  - per-cell reliability: red = implausible size or shape; yellow = low StarDist confidence; green otherwise. In the research evaluation, AUC was 0.814 for wrong cells, but about 70 % of wrong cells stay green;
  - three base64 JPEG overlays (quality 90, ~250 KB each): measured cells by side count, reliability, and cell area.
- **Artifacts** (`models/cellular/`, committed): `roi_cnn.onnx` (the image resize, ImageNet normalisation and sigmoid are inside the graph), `stardist.onnx` (tf2onnx), and `cellular_config.json`. The config holds every setting copied from `ml/cellular/config.yaml`, the SHA-256 of both files, the source commit and versions, and the export parity. All are written by `ml/cellular/export_web.py`. Files that do not match the SHA-256 give `503 MODEL_NOT_READY`. Loaded once at startup.
- **No PyTorch or TensorFlow:** both networks run in onnxruntime. StarDist's post-processing (candidate threshold, sparse NMS, polygons to labels) uses the `stardist` package's own functions, reproduced step by step in `pipelines/cellular/stardist_onnx.py`; TensorFlow is never imported.
- **Code:** `steps.py`, `cells.py` and `explain.py` are copied unchanged from `ml/cellular` (commit 7c26b0d). Only one guard is added: an image with no complete cells gets a plain image instead of the area overlay.
- **Parity:**
  - On 13 validation images, the export compared this path with the validated pipeline (PyTorch on GPU in mixed precision, TensorFlow). StarDist cells were identical in count and 100 % matched. Floating-point differences flipped one ROI block in 2 images. Largest differences: cells 0.91 %, ECD 0.12 %, CV 0.14 %, HEX 0.45 %. For comparison, the ECD error against the instrument on the test set is 5.8 %.
  - `tests/test_cellular_parity.py` runs the served pipeline on the 3 git-ignored reference images (`tests/data/cellular_reference/`, from the export). It allows ≤ 0.1 % difference from the exported web path, and cells ≤ 1 %, ECD and CV ≤ 0.2 %, HEX ≤ 0.5 % from the validated pipeline. Skipped where the data is absent. Print the table with `uv run python -m tests.test_cellular_parity`.
- **Validation (research, frozen test set, 197 images, against the instrument's ~110-cell counts):** mean cell area (MAPE 5.7 %) and CV (8.3 %) met their targets; ECD (5.8 %, target 5 %) and HEX (11.6 %, target 10 %) did not. HEX is systematically lower, by 5.7 points. See `ml/cellular/docs/phase/phase_7_final_test.md`.
- **Limitations:**
  - Validated only on 1296 × 972 images from one eye bank's specular microscope. The scale (µm/px) is specific to it, and other sizes get the `not_validated_size` warning.
  - About 9 s per image on a laptop CPU.

## Docker and the ONNX backbones

Two backbones are not in git: `domain_validator/resnet18_backbone.onnx` (about 45 MB) and `grading_backbone/resnet50_backbone.onnx` (about 94 MB). The Dockerfile regenerates both in a build stage:
- `scripts/export_domain_backbone.py` and `scripts/export_grading_backbone.py` run with pinned `torch==2.14.1` and `torchvision==0.29.1` (CPU).
- torchvision downloads the ResNet-18 IMAGENET1K_V1 and ResNet-50 IMAGENET1K_V2 weights from their versioned, hash-named URLs.
- Each script **checks that the exported backbone reproduces the reference output recorded with its trained model** (`classifier.json`, `grading_hybrid_rf.json`) on a fixed probe input, within 1e-3 (`scripts/backbone_check.py`). The build fails otherwise, so a backbone that differs from the one its model was trained with is never used.
- File hashes are not compared with training: the exporter folds batch-norm into the convolutions on the build machine's CPU, so the bytes differ between CPUs. A GitHub runner produced a different ResNet-18 file from the same torch, torchvision and weights. An export with different bytes but the same network passes (difference 5e-7); a different network fails (difference 9.7).
- After the check, the script writes `<file>.verified.json` with the file's SHA-256. At load, the service refuses a backbone without this record, one that has changed since it was verified, or one verified against a different model (`pipelines/image/backbone.py`).
- Local `.onnx` files are excluded from the build context.

Licences: torchvision is BSD-3-Clause; the pretrained weights were trained on ImageNet ([terms](https://pytorch.org/vision/stable/models.html)). COCO images were used for training and evaluation only and are not distributed.

For local development without Docker, generate the backbone once:

```
cd ml
.venv/Scripts/python.exe ../ml-service/scripts/export_domain_backbone.py ../ml-service/models/domain_validator/resnet18_backbone.onnx --verify ../ml-service/models/domain_validator/classifier.json
.venv/Scripts/python.exe ../ml-service/scripts/export_grading_backbone.py ../ml-service/models/grading_backbone/resnet50_backbone.onnx --verify ../ml-service/models/grading_hybrid_rf.json
```

Without the grading backbone the service still starts, but grading reports `failed`. Tests stub the backbone with synthetic embeddings, except one marked `real_backbone`, which is skipped when the file is absent.

## Tests

```
uv sync
uv run pytest
```

- **Without the backbone file:** tests that need the real validator are skipped; all other tests stub it.
- **Backend `MlServiceContractTest`:** checks captured responses against the backend DTOs. When the schema changes, regenerate `backend/src/test/resources/contracts/ml_service_analyze_responses.json` from this service. `MlServiceGradingContractTest` does the same for `ml_service_grading_responses.json` (`completed`, `missing_ecd` and `rejected_features`, captured with a training-set image and the real backbone).
